# Integrated browser player

The browser edition is a DOS workbench, not a video imitation. DOSBox-X runs the
assembled `.COM` files in WebAssembly and paints its VGA output into the canvas.
The modular build lives in `web/`; `dist/uber256-lab.html` is the same player with
every runtime asset embedded.

## Complete programme catalogue

`tools/build_web_catalog.py` generates `web/catalog.js` from two native sources of
truth:

- the 42-name `ORDER` list in `run-dosbox.sh`;
- the `ENTRY` records in `src/mega/mega_program.inc` and
  `src/mega/atlas_program.inc`.

For every standalone it records the program name, best matching capture in `docs/`
and the assembled byte count. Generation fails if the launcher and `src/*.asm` differ,
if a name is duplicated, if a `.COM` is absent or if no screenshot exists.

The UI groups boot targets as:

- integrated shows: MEGA, ATLAS and UBERSHOW;
- tiny intros: UBER70 and any future program of 128 bytes or less;
- 256-byte demos: current standalones from 129 through 256 bytes.

The 128-byte path is data-driven. A future standalone that assembles to 128 bytes or
less moves into the tiny-intro group automatically; no HTML edit is required.

## Thumbnail and source behaviour

The visual index always has a corresponding raw source view:

- Size-coded demo mode shows all 43 thumbnails (42 current standalones plus UBER70),
  with name search and 128/256-byte filters. A card selects that exact `.COM`, updates
  the URL hash and displays its complete `src/<name>.asm` before boot.
- MEGA and ATLAS show their ordered part lists. Before boot a card previews source;
  while running it writes a requested part to the signed `UBSYNC` control record.
- The DOS show writes its current part to the same record. The active thumbnail and
  source therefore follow actual emulated execution, including Space skips.
- UBERSHOW and UBER70 expose their preserved complete sources from `archive/`.

The source map is generated by `tools/build_web_sources.py`. Highlighting is performed
locally by the player and includes line numbers, instructions, registers, directives,
labels, strings, numbers and comments. No source is fetched after page load.

Thumbnails accept PNG, JPEG and animated GIF assets. The standalone builder converts
them to embedded data URLs, so the offline player has the same visual menu as Pages.

## Binary packaging

`build.sh` assembles every `src/*.asm`, MEGA, ATLAS, UBER70 and UBERSHOW. It copies all
46 bootable programs into `web/`. `tools/build_web_bundle.py` then embeds:

- all 46 `.COM` payloads;
- all 44 assembly sources;
- the generated programme catalogue and every referenced thumbnail;
- the DOSBox-X JavaScript/Wasm runtime and DOS font;
- the browser MIDI engine.

The HTML contains a SHA-256 content fingerprint. Verification decodes every COM,
checks the catalogue, source and thumbnail maps, rejects empty payloads and external
scripts/styles, and detects duplicate DOM IDs.

## Controls

| Control | Standalone | MEGA / ATLAS |
|---|---|---|
| Program menu | Select any exact COM | Select a show |
| Thumbnail | Select program and source | Preview source or jump to a running part |
| Left / Right | — | Previous / next part |
| Space | Program-defined | Skip to next part |
| Escape | Restore text mode and exit | End the show cleanly |
| Show / Hide source | Toggle full ASM panel | Toggle live-follow ASM panel |
| Full screen | VGA canvas | VGA canvas |
| Volume / Mute | DOS output | DOS output plus synchronized browser MIDI |

## Adding a demo

1. Add `src/name.asm`; it must assemble to at most 256 bytes.
2. Add `name` to `ORDER` in `run-dosbox.sh`.
3. Add a capture named `docs/name-atlas.png`, `docs/name.jpg`,
   `docs/name-a.jpg`, `docs/name-early.jpg` or `docs/name.gif`.
4. Add an `ENTRY` only if the effect also belongs in MEGA or ATLAS.
5. Run `./build-web-standalone.sh` and `python3 tests/test_web_catalog.py`.

The build fails instead of publishing a partially integrated demo.
